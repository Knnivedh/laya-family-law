## Four architectural flaws — fix before Run #1 (new; neither earlier consultation caught these)

1. **Isolated 9-pass encoding destroys cross-clause context & wastes 8× VRAM.** Running `[CLS] clause_i [SEP]` separately breaks coreference and Kannada/Kanglish pro-drop (zero-pronoun clauses like "ಮನೆಯಿಂದ ಹೊರಹಾಕಿದ್ದಾರೆ, ಚಿನ್ನ ಕೊಡುತ್ತಿಲ್ಲ" — "threw out of house, not giving gold" — have no explicit subject or marriage context in Clause 2). It also processes 9 × 288 = 2,592 tokens/example, forcing micro_batch_size = 1. **Fix:** encode `[CLS] full_question [SEP]` once (max_seq_len = 320, bf16); extract clause vectors via token-span attention pooling over the contextualised token embeddings inside each clause's character offsets. Every clause retains full-question context, clause-splitter errors become non-fatal, VRAM drops ~6× — allowing micro_batch_size = 8 (dynamic batch padding) with grad_accum = 2.
2. **ASL loss mismatch on [11, 4] and [28, 4] heads.** Asymmetric Loss is a binary multi-label loss, but each issue/fact has 4 mutually exclusive states (supported / denied / unknown / conflicting). Binary ASL across 4 states allows simultaneous supported=0.8 and denied=0.8, while standard softmax CE lets the ~85% unknown majority class crush rare positives (restitution: 118/7,500). **Fix:** class-balanced focal cross-entropy over the 4 mutually exclusive states per head (down-weighting unknown/absent to w₀ = 0.25, active states weighted by effective number β = 0.999 capped at 8×), OR model only the 3 active states as independent binary logits with unknown = all below threshold.
3. **Marginal per-head thresholds ignore Stage 2 AND-gate coupling.** Graph v4 maps (issue AND fact) pairs to sections (e.g. residence + coercive_eviction_or_lockout → pwdva-19). Optimising thresholds independently per head for marginal F1 under-recalls joint AND gates (0.75 × 0.75 = 0.56 joint recall). **Fix:** calibrate OOF thresholds directly against Stage 2 section-set exact match (with a precision floor guardrail), using Empirical Bayes shrinkage toward a shared prior τ₀.
4. **mmBERT-base unverified on Kanglish + over-strict 80% pre-sealed gate.** mmBERT-base (MIT) has broad multilingual pretraining, but Romanised Kannada (Kanglish) suffers heavy subword fragmentation unless pretrained on Indian transliterated text. Meanwhile, requiring ≥80% exact on every language before running the sealed test risks stalling for months on Kanglish dialect noise when the product target is ≥70%. **Fix:** run a 20-minute 1-fold smoke benchmark comparing jhu-clsp/mmBERT-base (MIT), google/muril-base-cased (Apache-2.0, natively pretrained on Indian scripts + Romanised transliterations), and FacebookAI/xlm-roberta-base (MIT), stratified by en / kn / kanglish. Set the pre-sealed gate to ≥75% overall and ≥70% per language. (Gate disagreement with ChatGPT's 80%-per-language gate is unresolved — see the plan's Phase D amendment note.)

## Q2 — Paraphrase augmentation (ranked)

**Template artefacts the classifier will overfit to:** syntactic skeletons & "tell" trigrams (e.g. "refusing to return" → demand_made; "kicked me out" → coercive_eviction_or_lockout), failing on euphemisms ("changed the locks while I was at my parents' house"); 1-clause = 1-fact neatness and clean punctuation, whereas real queries pack 3–4 facts into run-on emotional sentences without periods; absence of distractor facts (mentioning a child's age or wedding gold as background without claiming custody/stridhan — the exact cause of the 5 FPs on hma-13, pwdva-20, bnss-144).

**Ranked methods (best → worst):** (1) fact-bundle-conditioned narrative synthesis (LLM reverse-generation): sample multi-issue fact bundles (3–5 active facts + 1 incidental distractor), instruct an Apache-2.0 LLM (e.g. Qwen2.5-72B-Instruct) to write an emotional, first-person layperson query forbidding statutory keywords ("stridhan", "maintenance", "custody", "lockout", "cruelty"); (2) counterfactual minimal pairs on FN/FP boundaries ("we live separately" → divorce_asked=unknown vs. "I want to legally end our marriage" → supported); (3) spoken-register Kannada (Aadubhashe) + organic code-mixed Kanglish, generated directly in colloquial form, not translated English; (4) code-level structural perturbations (free, run on all 7.5k): strip punctuation, drop subject pronouns (pro-drop simulation), swap husband/wife/in-laws roles, merge clauses with "and" / "mattu"; (5) back-translation (avoid).

**Leakage-free & label-correct at scale:** generate strictly from JSON fact/issue schemas (never pass test/Kaanoon text into prompts); filter every record through the existing blind hash 8-gram + cosine (<0.80) leakage gate. Dual-verifier round-trip gating: feed the generated text (without labels) to two independent open-weight verifier models (e.g. Qwen2.5-32B-Instruct + Mistral-Small-24B, both Apache-2.0) prompted to extract the 11 issues and 28 facts. Keep only records where both verifiers match the target active labels 100% (discards ~20–25% noisy generations, yielding >97% label fidelity), plus a 5% human spot-check on Kannada/Kanglish.

## Q4 — Failure modes most likely missed (detection & mitigation)

1. **Multi-issue attention dilution & AND-gate cascade.** Dominant issues (maintenance/violence) suppress secondary issues (hma-27, welfare-principle) to p≈0.40; missing either half of an (issue AND fact) gate drops the entire section. Detection: stratify Val-500 exact match by active issue count (k=1, 2, ≥3); run a graph-path funnel audit separating issue-FN vs. fact-FN for each missed section. Mitigation: oversample k≥3 queries; add Stage 1b coupling boost (+0.10 prior to child facts when parent issue p>0.75); calibrate thresholds jointly on Stage 2 exact match.
2. **Kannada agglutinative negation & pro-drop.** Kannada encodes negation/modality in verb suffixes and omits subjects across clauses; Kanglish phonetic jitter (kodtilla/kodalla) fragments subwords. Detection: slice Val-500 F1 by en / kn / kanglish; run a 100-pair negation/modality suffix flip test (-illa / -alla / -beku / -adre). Mitigation: 1-pass contextual span pooling; pick backbone via Kanglish tokenizer fertility + smoke F1; phonetic jitter augmentation on Kanglish.
3. **Incidental background vs. actionable claim (FPs + silent failures).** Mentioning "we separated" triggers hma-13 FP; indirect queries score p≈0.42 across all heads, returning ∅ (2 silent failures on Fresh-20). Detection: requested vs. incidental confusion matrix on Val-500; log max_p across all heads on every ∅ prediction. Mitigation: train with explicit incidental negatives; non-empty fallback — if in_scope_p > 0.50 and predicted section set is ∅, relax active thresholds by 0.15 for that query.
4. **Val-500 i.i.d. grammar optimism.** Val-500 shares the exact synthetic grammar of the 7.5k train split; models memorise template structure and score ~12–15 pts higher on Val-500 than on human text. Detection: group-K-fold OOF holding out entire template families (not random splits); measure the random-split vs. group-split gap. Mitigation: never treat Val-500 alone as launch-ready; gate sealed runs on Human-300 + Real-Kaanoon-28.

## Q5 — Classifier design details

- **(a) Fusion (1-pass contextual span pooling):** global logit z_full(h) from [CLS] + global span attention, clause logits z_i(h) from token-span attention pooling over clause i's tokens in the same forward pass: p_requested(h) = max(σ(z_full(h)), max_{i=1..8}[(1 − g_i²)·σ(z_i(h))]), where g_i = σ(z_{i,neg/hyp/3p}).
- **(b) Clause veto gate (g_i):** (1 − g_i²) applies a smooth quadratic discount, not a binary cliff: at g_i = 0.50, clause confidence reduced by 25%; at g_i = 0.90, suppressed by 81%. Train g_i specifically on mixed-modality sentences (e.g. "If I file for divorce [hypothetical], can I still claim my stridhan and child maintenance [requested]?") so the gate learns clause-local scope rather than sentence-level rejection.
- **(c) Per-head threshold calibration (zero Val-500 leakage):** fit per-head temperature T_h on 5-fold OOF logits from the 7,500 training records (minimising NLL). Grid-search a single global threshold τ₀ ∈ [0.25, 0.65] maximising Stage 2 section exact match on OOF. Find per-head τ_h^OOF maximising F1.2 (recall-weighted F1) on OOF, then Empirical Bayes shrinkage: τ_h = [N_h+ / (N_h+ + 150)]·τ_h^OOF + [150 / (N_h+ + 150)]·τ₀ (keeps rare heads like restitution [N+ = 118] anchored near τ₀ while letting frequent heads like maintenance [N+ = 2,255] specialise). Run 1 pass of coordinate refinement on OOF for Stage 2 exact match subject to Micro-P_OOF ≥ 0.91, then freeze τ_h before touching Val-500.
- **(d) Training detail most likely to wreck generalisation:** over-training (>4 epochs) combined with uncalibrated rare-class priors. On 7.5k synthetic examples, Val-500 loss keeps falling past epoch 5 while unseen-paraphrase recall drops due to template memorisation, and rare facts (restitution, hma-13b, decree) stay stuck below τ = 0.50. Train for max 4 epochs (lr = 2e-5 encoder / 1e-4 heads, cosine schedule, 10% warmup, weight_decay = 0.01, bf16), checkpoint via template-grouped OOF, rely on post-temperature EB thresholds rather than τ = 0.50.

## Q6 — Evaluation design & pre-sealed gate

- **Val-500 inadequate** — it only verifies in-grammar learning. An out-of-grammar human benchmark is needed before burning the sealed sets.
- **Building the 300-question human holdout safely:** recruit 3–4 native speakers/law students who have never seen Brutal-230, Fresh-20, Kannada-8, or the template grammars. Give them abstract scenario cards (target issue/fact bundles + persona cues); instruct them to write natural 1–3 sentence queries in English (100), colloquial Kannada script (100), and Kanglish (100) without statutory jargon. Double-annotate the 11 issues + 28 facts (adjudicate disagreements), compile ground-truth sections via frozen Graph v4, run the blind hash 8-gram + cosine (<0.80) leakage filter against all sealed sets.
- **Amended go/no-go gate (≥75% overall / ≥70% per language):** section-set exact match ≥ 75% on Human-300 AND ≥ 70% on each language (EN, KN, Kanglish), plus ≥ 75% on Val-500 and ≥ 71% (≥20/28) on Real-Kaanoon-28. Precision guardrail: micro-precision ≥ 0.90 across all sets. Silent-output guardrail: empty section set (∅) ≤ 3% on in-scope queries. Category floor: ≥ 55% exact on each of divorce, residence, stridhan, custody, and joint_property.
