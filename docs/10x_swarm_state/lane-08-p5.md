## What was built

### 1. Student model — `src/laya_v7_student.py` (V71-P5-1)
- Canonical vocab (Lane 08 canonicalisation — the plan fixes counts, not
  lists; see the module docstring for provenance):
  - 11 issues: maintenance, custody, stridhan, residence, violence,
    divorce, joint_property, restitution, dv_injury_compensation,

    safety [3] (none / threat_or_harassment / imminent_physical_or_child_danger).
  - `time` uses the plan's 5 modality labels; `src/laya_v7_schema.py`

- `LayaV7Student` (lazy torch import): one shared encoder + 6 linear
  heads, CLS pooling, single forward pass; param budget enforced

- Pure-python helpers, unit-testable without torch: `pad_to_bucket`
  (64/128/192, raises over 192), `build_student_inputs` ([full_q] +
  clauses, capped at batch 8), `decode_logits`, `select_tier`
  (mode="auto" decision logic), `vocab_fingerprint` (SHA-256, recorded
  in every run manifest). Vocab version: `v71-p5-1`.
- Backbone is NOT hard-pinned: candidates are the plan's examples
  (6-layer distilled mmBERT / ModernBERT-small / MiniLM-L12
  multilingual). The exact checkpoint + licence must be verified at
  execution against Lane 06's audit — only Apache-2.0 / MIT / BSD-3
  weights may ship.

### 2. Distillation — `scripts/distill_student.py` (V71-P5-1)
- Loss per head: `alpha * KL(teacher/T || student/T) * T^2 + (1-alpha) * CE(hard)`,
  defaults T=2.0, alpha=0.7, epochs=3, lr=2e-5, seed=42; head weights
  issue 1.0 / fact 1.0 / sex 0.5 / role 0.5 / time 0.5 / safety 2.0.
- Teacher soft targets cached to `--teacher-cache` (.npz) so re-training
  does not re-run the teacher.
- Corpus validation: every C2 record checked against the student vocab;
  the script REFUSES to train (exit 2) on unknown issue/fact keys or bad
  labels. Batch size / max_seq_len above the plan caps (8 / 192) are
  refused, not clipped.
- Safety head is KL-only: the C2 corpus schema carries no safety label,
  so the script does NOT default its hard target to "none" (that would
  teach the student to never fire safety). Flagged for Lane 02/03: if a
  safety label is added to the corpus schema, wire it into the hard
  targets at merge.
- Teacher interface coded against (plan §1.2/§5.2):
  `laya_v7_classifier.LayaV7Teacher.from_pretrained(path, device)` +
  `.teacher_logits(texts)` returning the 6 head-logit dicts in student
  row order. Missing/wrong teacher fails loudly with the expected
  interface printed.

### 3. ONNX export + Parity Guard — `scripts/export_student_onnx.py` (V71-P5-2)
- Export: pure PyTorch -> ONNX opset 17, inputs
  (input_ids, attention_mask) -> 6 head logits, dynamic batch axis;
  `quantize_dynamic` QInt8 (MatMul/Attention); ORT `ORT_ENABLE_ALL`
  fusion (Gemm/LayerNorm/GELU) at session load.
- Deterministic shape-bucket padding (64/128/192); batch permutation
  invariance checked (forward vs reversed vs shuffled, tol 1e-4 per
  plan §7.4).
- Sealed paths are refused as probe sets (probe must be the held-out
  synthetic dev split, never `test-bank/sealed/`).
- **Parity Guard — exact thresholds implemented** (the plan's §5.2 line
  is truncated mid-sentence in `docs/10x_plane.md`, so Lane 08
  completes it from the plan's own tolerances — stated here, not
  quoted as plan text):
  - `max_abs_diff <= 0.03` (FP32 PyTorch vs INT8 ONNX softmax probs,
    all heads; same 0.03 as the T4 parity gate, same magnitude as the
    measured bf16-vs-fp16 drift 0.0281)
  - `0` argmax flips on any head
  - micro-F1 drop `<= 0.005` (0.5%, plan §5.3; computed in-script when
    the probe file carries hard labels — micro-F1 = accuracy over head
    rows — otherwise recorded as not-measured and enforced end-to-end)
  - Breach => exit 3, artifact renamed to `*.rejected.onnx`, never
    served as `models/student_int8.onnx`.

## Tiered mode="auto" serving design (V71-P5-4)

| Tier | Mode | Artifact / device | Plan target (NOT measured) |
|---|---|---|---|
| 1 | `student_onnx_gpu` | `models/student_int8.onnx`, ORT CUDA EP | < 50 ms/Q |
| 2 | `student_onnx_int8_cpu` | `models/student_int8.onnx`, ORT CPU EP | < 0.5 s/Q |
| 3 | `laya_teacher_cuda` | Lane 03 teacher / PIXMELT laya, CUDA | ~0.13 s/Q (v7 baseline 0.133 s/Q mean) |
| 4 | `evidence` | zero-model evidence fallback, EN-only | < 1 ms/Q, emergency only |

Selection (`select_tier` in `src/laya_v7_student.py`): CUDA + ONNX
present -> tier 1; ONNX present -> tier 2; CUDA + teacher -> tier 3;
else tier 4. The caller falls through on load failure. All latencies
above are plan §5.2/§5.3 targets; no measured latency is claimed
anywhere in Lane 08's deliverables.
